# Final Submission Checklist

## Code quality

- [ ] Backend tests pass.
- [ ] Frontend tests pass.
- [ ] Frontend production build passes.
- [ ] Full CRUD works through the browser.
- [ ] CSV and JSON downloads open correctly.
- [ ] Invalid locations and dates show clear errors.
- [ ] Current-location permission denial is handled.
- [ ] Desktop, tablet, and mobile layouts are usable.

## Repository hygiene

- [ ] `.env` files are not committed.
- [ ] No API keys or access tokens are committed.
- [ ] `weatherscope.db` is not committed.
- [ ] No `.venv`, `node_modules`, `dist`, caches, or logs are committed.
- [ ] `package-lock.json` is committed.
- [ ] Root `README.md` renders correctly.
- [ ] Setup commands work from a clean clone.
- [ ] Repository is public, or reviewers have collaborator access.
- [ ] Clone/download access is enabled.

## Assessment requirements

- [ ] The application displays “Yateen Sakhare”.
- [ ] The application displays PM Accelerator information and mission.
- [ ] Real weather data is used.
- [ ] Current location works.
- [ ] Five-day forecast works.
- [ ] SQL/NoSQL persistence is demonstrated.
- [ ] Create, Read, Update, and Delete are demonstrated.
- [ ] At least one external integration beyond weather is demonstrated.
- [ ] Data export is demonstrated.
- [ ] README explains setup, methodology, and features.
